Mismatches found while tracing

  1. Edge forwards an archive receipt as PUT (platform/crates/public-api/src/archives.rs:636); chatgpt and claude route /v1/ai-archives/receipt for POST only, so a live import would be refused.
  2. Knowledge fetches a digest manifest from v1/channel-digest/manifests/{id} (knowledge/crates/knowledge/src/channel_digest_recap.rs:213); channel-digests serves /v1/manifests/{id} (integrations/channel-digests/src/api.rs:63).
  3. channel-digests reports operation status "completed" (src/intake.rs:94), which is not a value of OperationStatus; the terminal value is Succeeded.
  4. The X scan command is x.bookmarks.scan_requested.v1 in X's code and x.bookmarks.snapshot_requested.v1 in the platform README.

Traced in source under repos/; each step cites the file and line. Not wired today: extractor to knowledge, AI archive and social facts to knowledge, github to vault and back, and every producer of platform.notification.raised.v1.

Deployment

The host is frozen as of 2026-08-21. Nothing is deployed to it or changed on it. Only Platform's three units were ever installed, on 2026-08-19 (milestone 10), and that slice ran end to end. The rest of this view is the target every service must fit, read from the deploy files and config defaults in each repository.

Where the documents disagree

  1. Port 9467 is the telegram-webhook operator listener and also the extractor admin listener; both example configs bind 0.0.0.0:9467.
  2. Port 9084 is the default listener for threads, chatgpt and claude alike.
  3. Edge routes /v1/k, /v1/vault, /v1/social, /v1/ai, /v1/chatgpt and /v1/claude to ports 8091 and 8093 to 8097, and no repository binds those ports yet.
  4. The PostgreSQL data directory is /mnt/nvme/ratatoskr/postgres in the storage table and /mnt/nvme/shared-postgres/data in the container note of the same document.
  5. The ufw rule opens 9464:9466 in the platform deploy README and 9464:9468 in DEPLOYMENT_TARGET.md.
  6. Extractor, github and channel-digests listeners are missing from the DEPLOYMENT_TARGET.md port table.

On the bus, outside the registry

  • cmd.content.capture.requested.v1: platform to extractor; the one command shape a client capture and a webhook both produce (DEPLOYMENT_TARGET.md, extractor README)
  • evt.content.document.extracted.v1: extractor to knowledge, carrying Document IR (extractor README)
  • cmd.x.capture.requested.v1, and the instagram and threads equivalents: per-provider routing of social.capture.requested.v1 (platform NATS README, x README)
  • cmd.github.sync.requested.v1: the platform scheduler to github (github README)
  • cmd.vault.target.desired.v1: github to vault, the desired backup state (github and vault READMEs)
  • evt.platform.notification.raised.v1: the only filter on the telegram dispatcher's durable consumer (platform NATS README)

Registry and READMEs disagree

  • platform.operation.reported.v1 is also published by threads and channel-digests per their docs; the registry lists neither.
  • knowledge.analysis.completed.v1 is consumed by x per its README; the registry lists only instagram.
  • platform.operation.progressed.v1 is registered, but the platform README says Platform does not publish it today.
  • The contracts labels in workspace.toml are loose names: portable-export, knowledge.search, github.catalog and platform.public-api match no registry id.

Public API

Platform owns the public HTTP surface and generates its OpenAPI 3.1 document from its own routes; contracts owns the types the routes carry (platform ADR-0006). Web generates its client with openapi-typescript 7.13.0 and mobile with openapi-generator 7.25.0, each pinned by a lock file.

Profiles & build order

Which repositories each manifest profile groups, and the order a cross-repository change has to move in. The profiles are declared in workspace.toml; the Compose files that will start them are planned, and the one integration profile running today is web-operational. A repository's manifest dependencies all sit in earlier layers, so a layer can be built and verified once the layers to its left are green. Contract changes still follow expand, migrate, contract.
