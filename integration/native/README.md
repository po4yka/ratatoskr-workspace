# Native multi-service smoke

This directory drives each cross-repository flow of the Ratatoskr fleet through Platform Edge's HTTP API on one machine, with no Docker. It exists because the Docker profiles under `integration/compose/` cannot run on the machines the fleet is developed on, and because those profiles never exercised the services together under the deployed bus authorization with the checked-in PostgreSQL provisioning. It is the only end-to-end evidence the XR-021 change can produce, so its honesty rules are part of it: a flow that was not run, or a hop that was stubbed, is written down as such and never reported as passed.

It is a manual, machine-dependent run. It is not a CI gate, and nothing in CI runs it. `integration/tests/native_smoke_contract_test.sh` checks the scripts themselves (the prerequisite check, `--list`, `--prune`, the safety rules, the fixtures and the fakes) without building or starting any service.

## What it runs

Services are built natively with `cargo build --release --locked` from the pinned submodules under `repos/` (read only; every flow ends with a check that each repository it used is still clean), configured only through the `RATATOSKR__*` keys of each repository's `deploy/systemd/*.conf.example`, and started with `lib/envrun.py`, which behaves like the `EnvironmentFile` of the shipped unit files. NATS is `nats-server` under the deployed ACL of Platform's `deploy/nats/ratatoskr.conf` with fresh nkeys from Platform's own `render-nats-config`. PostgreSQL is a private cluster under the state directory, provisioned only with the checked-in files in the order Platform's `deploy/README.md` documents: `01-database-and-roles.sql`, the first Edge start, `02-grants.sql`, then each service's `deploy/postgres/role.sql` before that service's first start.

A flow that needs Edge's routes runs on the production loopback ports of `docs/DEPLOYMENT_TARGET.md` (Edge 8080 and 9464, Knowledge 8091 and 9081, GitHub 8092 and 9095, ChatGPT 8096 and 9085, Claude 8097 and 9086, channel-digests 8098, 9469 and 9470, X 9087, Instagram 9082 and 9083, Threads 9084, extractor 9088, Telegram 8182, 9467 and 9468, NATS 4222 and 8222), because Edge's validation of those routes is a contract (R3-17). The one exception is PostgreSQL on `127.0.0.1:54329`. Because the ports are fixed, only one flow can run on the machine at a time: `run.sh` takes `$RATATOSKR_SMOKE_DIR/lock` and refuses to start when a port of the flow is held by another process, printing the holder's pid and command and exiting 3. It never stops a process it did not start.

## Usage

```sh
integration/native/run.sh --list              # the flows, their binaries and ports
integration/native/run.sh --dry-run f1        # exit 0, or exit 3 with one MISSING line per missing prerequisite
integration/native/run.sh f0 f1 f2            # run flows one at a time, in the order given
integration/native/run.sh --prune             # remove what earlier runs left under the state directory
RATATOSKR_SMOKE_REF=origin/main integration/native/run.sh f1 f6   # run against a ref of every repository a flow uses instead of the pinned commits
```

F6 resumes the databases and blob roots that F1 keeps, and every other flow starts from nothing, so run F6 right after F1 (`run.sh f1 f6`) and run the others in any order.

By default a flow builds and reads the commits the workspace pins (the submodules under `repos/`). `RATATOSKR_SMOKE_REF` exports that ref of each repository the flow uses into `$RATATOSKR_SMOKE_DIR/src` with `git archive` and builds from there, so a flow can run against the heads the children publish before the workspace pins them; the submodules are not touched and stay clean. A binary is rebuilt when the commit it was built from differs from the commit the flow runs.

One Python interpreter serves the whole run. `lib/common.sh::py_select` takes the first candidate that passes a probe (an HTTP server on an ephemeral loopback port that the same interpreter fetches from with `urllib` within 3 seconds, and `import cryptography`): `$RATATOSKR_SMOKE_PYTHON`, then the interpreters mise installs (newest first), `/usr/bin/python3`, `/opt/homebrew/bin/python3` and the first `python3` on `PATH`. `run.sh --dry-run` exits 3 with `MISSING: python with HTTP serving and cryptography` when none passes, and `result.txt` names the interpreter that ran.

The state directory is `$RATATOSKR_SMOKE_DIR`, default `$HOME/.cache/ratatoskr-smoke/XR-021-r6`. It must be an absolute path outside the workspace checkout, and `--prune` only touches a directory that carries the `.ratatoskr-smoke-dir` marker the smoke wrote. The evidence summary of each flow goes to the gitignored `evidence/XR-021-r6/<flow>/`: `asserts.txt`, `result.txt` with the verdict, the hops that were stubbed, seeded or not exercised, and every configuration deviation from the shipped examples, plus redacted request and response records. Databases, blobs, staging, keys and rendered configs hold secrets and are deleted when a flow ends; logs and the redacted evidence stay. F1 keeps its databases, blobs, keys and the NATS store for F6, which needs the facts F1 produced.

Prerequisites: `nats-server` 2.10 or later, `initdb`, `pg_ctl`, `psql` and `pg_config` for PostgreSQL 17 with the pgvector files installed (the extension is not trusted, so Knowledge's `role.sql` creates it as the administrator), `cargo` with the toolchains the repositories pin, a Python 3 that serves HTTP and imports `cryptography` (chosen by `py_select`, see below), `perl` (the probe's watchdog), `jq`, `curl`, `lsof`, `rg` and `git`, at least 12 GiB free on the volume that holds the state directory, and every port of the flow free. Docker is not needed.

Builds use each repository's shipped release profile. `CARGO_PROFILE_RELEASE_DEBUG=0` is never set, because it makes the sqlx proc-macro dylib fail to load on macOS 27 (`mis-aligned LINKEDIT string pool`); `lib/build.sh` retries a build once with `CARGO_PROFILE_RELEASE_STRIP=none` when it sees that error and records the retry. A target directory is deleted right after its build, and a build is refused below 6 GiB free.

## Round 5

Round 5 is the first time every flow was run through `run.sh` as committed (commit `4d95fa7` of the workspace), one at a time, on the developer's Mac (macOS 27, arm64, nats-server 2.15.1, PostgreSQL 17 with pgvector, Python 3.12.15 chosen by `py_select`), against the `origin/main` of every child as of 2026-10-13: platform `3275d52`, extractor `b565523`, knowledge `577ccc3`, chatgpt `6e95087`, claude `272b683`, channel-digests `65a5df7`, telegram `a8a337a`, x `cf21321`, instagram `171caf1`, threads `e8cb95c`, github `80aaa84`, vault `b810b26`. The order was F0, F1, F6, F2, F3, F4, F5, F7. Every flow ended `PASS`, every submodule stayed clean, and the NATS log had no ACL violation outside the deliberate probes of F0. The evidence summaries are in the gitignored evidence directory of that round; `result.txt` of each lists the commits that ran, the interpreter, the faked and seeded hops and the configuration deviations.

Running them found these defects, all in the harness (no service defect stopped a flow):

- The first honest run could not start: the interpreter choice, `q` swallowing psql errors (an assertion over two empty strings passed), the removed `knowledge.ingest_failures` table, Homebrew's Python 3.15 accepting a connection to a fake and never answering (not reproduced by the probe on 2026-10-13, which passes it; the choice is now explicit).
- Stale state between flows: logs and the control files of the fakes (`fake-fail`, `github-description`, `deleted.list`) survived a flow and changed the first answer of a fake; both are now removed when a flow starts.
- A fake whose control was an empty file read as unset (`github-stall`), so the stalled-provider leg never stalled anything; `secret` stripped `/`, `+` and `=` from base64 and so produced fewer than the 32 characters `conf_github` demands in most runs.
- Assertions written against behaviour the services no longer have or never had: readiness that "stays 200" while the broker is down (Knowledge's readiness follows the broker, `services/knowledge/tests/ingest_outage.rs`), a removal fact for a post the owner never preserved (`x-sync` `remove_owner_source` publishes nothing then), a terminal "unavailable" within 150 s for a transport failure that X retries for about 40 minutes, a wrong-length blob log class that is now `peer blob verification failed`, a `track` action that reports a provider failure in a 200 body.
- Fixtures: one-line PDFs are judged to have no text layer, a 9 MB-text PDF exceeded the page cap before the event limit, and the ChatGPT series-3 export that the old F6 could not find was removed by the Civet conversation deletion (its only holder), not rebuilt differently: `archives.py` is byte-deterministic (a self-test builds twice) and the digest is now recorded at upload time in `$S/fx/<name>.sha256`.
- A tap that buffered a whole response would have held the dispatcher's progress stream back; it now passes `text/event-stream` through frame by frame. The channel-digests worker exits with `Database(Schema)` when it starts together with the API, because both apply the schema (`src/runtime.rs` lines 106 and 145, `src/database.rs` line 60); the flow starts the API first and the race is reported to the owner as an observation, not a blocker.

New legs, written with the Round 5 behaviour they cover: F0 (23 durables including the five `*_deletion_acks`, `platform_stream_erasure`, the deployed ACL for stream deletion, the erasure command and Knowledge's acknowledgement, the pull grant of each producer on its own acknowledgement durable and on no sibling's, the bus lag series on 9464 for a durable nobody consumes, the alert rule file parsed as YAML); F1 (abandoned, expired and digest-mismatch staging reaped within two sweep intervals, a dead token and a digest mismatch replaced by a new token, readiness following the staging root, the Claude knowledge file verified, with a wrong digest and referenced only, a corrupt archive per provider, repeated keys, the 401 stand-in on 8097, a 256 MiB archive timed); F2 (one `document_id` for two captures of one digest, Claude and ChatGPT conversations of 2 MiB and 7.85 MB, a provider credential that answers 401, 402 and 404 for two minutes, a 400 Termed at its first delivery, Knowledge's database role locked out for 90 seconds, a message that is not an envelope); F3 (a progress stream held 32 seconds is followed over at most two requests with no `follow_frame_failed`, and the completion edit arrives); F4 (the retention timer nulls an old body and keeps provenance, the scheduler occurrence creates a scheduled run); F5 (a recaptured deleted post leaves the library); F6 (a tombstone resent after 150 seconds and acknowledged once, stream erasure of the deleted conversation's fact with its neighbours kept, the foreign-subject probe acknowledged refused, the owner kept after a mapping change for both providers, the concurrency leg).

## What is faked, seeded or not exercised

The fakes are `fixtures/fake_openrouter.py` (with `RUN/fake-status`, a schedule of 401, 402, 404 and 400 answers that ends in 200), `fake_bot_api.py`, `fake_x_api.py` (HTTPS behind a throwaway CA from `make_pki.py`), `fake_github.py`, `stand_in_receipt.py` (a 401 in place of the Claude receiver) and the recording `tap_proxy.py`; `big_archives.py` and `upload_cli.py` build and upload the large conversations of F2. Each is labelled in the `result.txt` of every flow that uses it, and nothing a fake produced is reported as a live provider result. Principals are seeded by SQL (`fixtures/platform-seed.sql`) where a flow only needs one to exist, and labelled so; F1 pairs devices through the real pairing API. Configuration deviations from the shipped examples are limited to addresses, paths under the state directory, the CHANGE-ME secrets, `PLATFORM_ACCOUNTS` user ids and the per-flow keys a flow names, and every one is listed in the flow's `result.txt`.

The smoke cannot show: real MTProto acquisition (so the partial-acquisition path of channel-digests), live X, Meta, Threads and OpenRouter responses (the success legs of Instagram and Threads, the quality of a recap), the Export Agent's macOS keychain pairing and Swift client (an owner-run step: `swift test` of that repository is its evidence), TLS termination by `cloudflared`, systemd sandboxing and the host's group permissions on the Telegram blob root, the Raspberry Pi's glibc and 16 KiB page-size behaviour, and anything that needs more than single-machine loopback. Process lifetime and restart behaviour are exercised only where a flow stops a process on purpose.

## Safety rules the contract test checks

No script writes outside `$RATATOSKR_SMOKE_DIR` and the gitignored `evidence/`. No script contains `pkill`, `killall` or a `kill` of a pid it did not record: processes are stopped through pid files with SIGTERM, a 15 second wait and then SIGKILL of that pid. `--prune` removes only paths under the state directory. A busy port is reported with its holder and never freed.
