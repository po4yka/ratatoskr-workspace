## a. `ob login`

- Options: `--email`, `--password`, `--mfa`. No environment variable or file option. [code] [help]
- When stdin is not a terminal, the prompt reads all of stdin up to EOF and removes trailing
  whitespace. `ob login --email E --mfa C < password-file` therefore keeps the password out of
  argv. [code]
- Only one prompt can read stdin, because the second prompt waits for an `end` event that has
  already fired. Pass `--email` and `--mfa` in argv. [inferred]
- `login` has no `--json` option (`error: unknown option '--json'`, exit 1). A failed login prints
  `Login failed:` and exits 2. [help] [code]
- The undocumented variable `OBSIDIAN_AUTH_TOKEN` replaces the stored token file. [code]

## b. `ob sync-setup`

- Only `--password`. Without `--json`, a missing password is read from stdin. With `--json` and no
  `--password`, it prints `Password not provided.` and exits 2. [code]
- A vault with managed encryption needs no password. [code]
- Key: `scrypt(NFKC(pw), NFKC(salt), N=32768, r=8, p=1, 32 bytes)`, checked through `/vault/access`.
  A wrong password exits 2 (`Failed to validate password.`); an unknown vault exits 3. [code]

## c. State

Root: `${XDG_CONFIG_HOME:-$HOME/.config}/obsidian-headless` on Linux, `~/.obsidian-headless` on
macOS. [code]

| Item | Path | Mode | Content |
|---|---|---|---|
| Auth token | `<root>/auth_token` | 0600 on creation | plaintext |
| Vault config | `<root>/sync/<vaultId>/config.json` | 0600, directory 0700 | plaintext JSON with `encryptionKey` (base64 of the derived key) |
| Sync state | `<root>/sync/<vaultId>/state.db` | umask | SQLite index |
| Sync log | `<root>/sync/<vaultId>/sync.log` | umask | all console output |
| Lock | `<vault>/<configDir>/.sync.lock` | | lock directory |

Nothing is encrypted at rest, and no keychain is used. [code]

## d. Does `ob sync` need the password again?

No. It uses the token and the stored `encryptionKey`. A missing token or key exits 2. [code]

## e. Endpoints

`https://api.obsidian.md` (sign-in, vault list, access, create), `wss://<host>` for sync (the host
must end with `.obsidian.md`), `https://publish.obsidian.md` and publish site hosts. No telemetry
or update check. [code]

## f. Modes and conflict strategy

- Modes: `bidirectional` (default), `pull-only`, `mirror-remote` (reverts local edits and removes
  local-only files). [code] [help]
- `merge` (default): a three-way diff-match-patch merge of `.md` files that changed on both sides,
  against the last synced server version. With no base: the remote wins if the local file is less
  than 3 minutes old, otherwise the newer mtime wins. [code]
- `conflict`: the local text goes to `<name> (Conflicted copy <device> <YYYYMMDDHHMM>).<ext>` and
  the remote text replaces the original. [code]
- Not under the strategy: config `.json` files get a shallow merge, remote over local; other
  non-`.md` files keep the local version (`Rejected server change`). [code]

## g. Signals for a supervisor

- `ob sync` has no `--json` output. Its output goes to stdout and stderr and to `sync.log`. [code]
- Exit codes: 0 fully synced (one-shot); 1 sync failed (also a held lock, an expired subscription or
  a deleted vault in one-shot mode); 2 no token, no key, or login or password failure; 3 no
  configuration or vault not found. [code]
- **An expired or revoked token does not stop the process.** It logs `Failed to authenticate:` and
  tries again for ever, in both modes. It waits 5 seconds after the first failure, and the wait
  grows up to 5 minutes. [code] (Corrected on 2026-10-14: the first record said every 30 seconds.)
- Conflicts have no exit code. Log lines: `Conflicted copy stored`, `Merging conflicted file`,
  `Merge failed.`, `Rejected server change`, `Renaming conflicted file`, `Sync error:`,
  `Disconnected from server`, `Fully synced`. [code]
- SIGINT and SIGTERM stop it cleanly. [code]

## Unknown

- The single-read limit of stdin and the continuous-mode exit code were read, not run.
- The token lifetime and the server message for an expired token. Spike 3.1 measures them.
- `OBSIDIAN_AUTH_TOKEN` is undocumented and can be removed in a later release.

## Decision

Recorded in design D3 and D4: both passwords go to `ob` on standard input from
`$CREDENTIALS_DIRECTORY`; only the one-time MFA code is in argv; the `hidepid=invisible` fallback is
not needed; the supervisor stops a connection that logs `Failed to authenticate:` for 5 minutes;
the package version is pinned.
